# 사례 자동 업그레이드: 영상 1개 → 사례 페이지 (2026-10-16 병한님 설계)

목표: 병한님이 휴대폰으로 영상 하나만 올리면, 사람 손을 거의 거치지 않고 지역 사례 페이지가 생기고 쇼츠와 짝이 맞춰지게 한다.
단계마다 끝내고 main 에 반영한다. 이 문서는 단계가 끝날 때마다 채운다.

## [1] 구글 드라이브 인박스

- 폴더: `G:\내 드라이브\폐차_인박스` (구글 드라이브 데스크톱 앱이 PC에 G: 로 연결). 없으면 스크립트가 만든다.
- 누가: PC 사례 가져오기 예약 작업(13:40·13:55, 지시문 `docs/pc-case-import-prompt.md` 3-3~3-5)이 사례 고르기 전에 먼저 돈다.
- 스크립트: `scripts/inbox_cases.py` (`scan` → Claude 가 `answer.json` 작성 → `apply gN` → `report`).
- 묶기: 파일의 수정 시각 순으로 늘어놓고, 앞 파일과 30분(`GROUP_GAP_MIN`)보다 떨어지면 다른 차로 본다. 영상(.mp4 등)·사진(.jpg/.png, 간편조회 캡처·등록증 포함)·녹음(.mp3/.m4a 등)을 받는다.
- 지역을 알아내는 순서
  1. 영상 마지막 5초(`TAIL_SEC`)의 말을 faster-whisper `medium` 모델로 글로 바꾼다(녹음 파일은 앞 60초). 받아쓰기가 틀릴 수 있으므로 Claude 가 법정동 이름으로 바로잡아 정식 이름으로 적는다.
  2. 위치 정보(사진 EXIF GPS, 영상 location 태그). 거래처 폐차장·수출 사무실(`data/partner_locations.json`: 파주 마이카스, 평택 진승, 양주, 안산, 수원 장안구 수출 사무실, 단산 해체장) 반경 안이면 무시한다. **거래처 좌표가 비어 있는 동안(2026-10-16 현재)은 GPS 로만 정한 지역은 쓰지 않고 보류**한다(거래처 위치를 손님 동네로 잘못 적지 않게). 주소가 정해지면 `lat`·`lon` 을 채운다. 좌표를 동네 이름으로 바꾸는 일(역지오코딩)은 아직 넣지 않았다. 손님 위치를 외부 서비스로 보내지 않으려는 것이며, 넣을 때 따로 정한다.
  3. 등록증 사진: 주소의 시군구·동만 읽는다. 그 파일은 `apply` 가 바로 지운다(드라이브 휴지통으로 가서 30일 안에 되살릴 수 있음, 휴지통 비우기는 하지 않음). 저장소·공개에 절대 넣지 않는다.
  - 차번호·연식·압류는 간편조회 캡처에서 읽어 **원본 메모에만** 적는다(사례 메모로 옮길 때 `pc_cases.py` 가 표에 없는 칸을 버림).
  - 그래도 지역(또는 차종)을 모르면 그 차는 보류한다. 파일은 인박스에 그대로 두고, 보고에 "확인 필요: ○○"로 적고, `cases/input/인박스-확인-필요.md` 에 올린 시각·파일 수·차종·이유만 적는다(위치·차번호·말 내용은 넣지 않음).
- 정리된 차: `폐차사진원본\우선\YYYYMMDD_동_차종연식_상황` 폴더를 새로 만든다(같은 이름이 있으면 `_2`). 영상·사진은 폴더 바로 아래, 간편조회 캡처·녹음·받아쓴 말(`말.txt`)은 `자료\` 아래(사례 사진으로 뽑히지 않게). 메모.txt 의 날짜는 묶음에서 가장 이른 파일의 날짜.
- 미리보기: Claude 는 원본을 직접 보지 않고 `.cases_staging/inbox/gN/` 의 미리보기만 본다. 미리보기는 위치 정보를 지운 새 파일이다.
- 하루 건수: `pc_cases.py scan` 기본값이 밀린 대상(조건을 갖춘 원본 폴더)이 3건보다 많은 동안 5건, 아니면 3건이다(`DAILY`, `BACKLOG_DAILY`).
- 공개용 사진의 위치 정보는 지금처럼 `pc_cases.py mask` 가 새 파일로 저장하며 지우고, `check_pages.py` 가 남은 정보를 막는다.

## [2] 영상에서 사진 뽑기

- 원본 사례 폴더에 사진(.jpg/.png/.webp)이 없고 영상(.mp4/.mov 등)만 있으면, `pc_cases.py scan` 이 그 건을 "사진 없음"으로 빼지 않고 대상으로 넣는다.
- `pc_cases.py prepare` 가 `video_frames` 로 장면 후보 12장(`FRAME_CANDIDATES`)을 `.cases_staging/cN/p01.jpg…` 로 만든다.
  - 마지막 5초(`FRAME_SKIP_TAIL`, 지역·차종을 말하는 부분)는 쓰지 않는다.
  - 차를 한 바퀴 돌며 찍은 영상은 장면이 서서히 바뀌므로, 쓸 구간을 12칸으로 나눠 칸마다 가장 선명한(라플라시안 분산이 큰) 한 장을 고르고, 바로 앞 장면과 색 분포가 거의 같으면(바타차리야 거리 < 0.03) 뺀다. 영상이 여러 개면 길이에 비례해 나눈다.
  - 뽑은 장면은 새로 만든 파일이라 위치 정보(EXIF/GPS)가 없다. 이후 `mask` 가 다시 새 파일로 저장하고 `check_pages.py` 가 남은 정보를 막는 것은 같다.
- 루틴(지시문 6단계)이 미리보기에서 서로 다른 4장을 앞 → 뒤 → 옆 → 계기판 순으로 고른다. 번호판 글자가 보이는 장면은 가리지 않고 건너뛴다(자동 번호판 인식은 넣지 않음, 고르는 눈은 Claude).

## [3] 영상에서 한 말

- 원본 폴더에 대본·녹음용 문장 .txt 가 있으면(`pc_cases.spoken_file`: 이름에 대본·문장·멘트·녹음이 들어간 것 → 없으면 메모·반영됨·문자 백업이 아닌 .txt 가 하나뿐일 때 그것), `pc_cases.py stage` 가 `cases/input/<폴더>/대본.txt` 로 옮긴다. 인박스에 올린 .txt 는 `inbox_cases.py apply` 가 원본 폴더의 `대본.txt` 로 넣는다(두 번째부터는 `자료\`).
- 자동으로 받아쓴 말(`자료\말.txt`)은 대본이 아니다. 지역·차종을 알아내는 데만 쓰고 페이지에 넣지 않는다.
- `build_cases.read_spoken` 이 읽어 사례 페이지 "진행 방식" 다음에 "영상에서 한 말" 칸(인용 상자, 줄바꿈 유지)으로 넣는다. 문장은 고치거나 꾸미지 않는다. 800자(`SPOKEN_MAX`)까지 받는다.
- 메모와 같은 검사(`build_cases.banned_text`: 금액·시세, 결과 약속, 수출 된다/안 된다 단정, 고객 정보)에 걸리면 그 사례는 처리하지 않고 이유를 알린다.
- 블로그 초안은 같은 문장을 쓰지 않고 따로 다듬는다(`폐차119_블로그/CLAUDE.md` 절대 규칙에 추가).

## [4] 쇼츠 끼우기

- 스크립트 `scripts/shorts.py`. 매일 루틴(`docs/daily-routine-prompt.md` 3-0)이 `python3 scripts/shorts.py match` 를 사례 빌드 전에 돌린다. 지금 짝 목록은 `python3 scripts/shorts.py show`.
- 읽는 곳: `https://www.youtube.com/feeds/videos.xml?channel_id=UCZrqa9lcMlGWDHHitO0ie0w` (@pecha-export, 최근 15개). 주소가 `/shorts/` 인 영상만 본다.
- 짝 맞추기(`match_case`): 제목+설명(띄어쓰기 무시)에 사례의 차종이 있고
  1. 사례의 동 이름이나 시군구 이름이 있으면 그 사례(그런 사례가 하나일 때만)
  2. 없으면 "○○○○년식"이 사례 연식과 같고 그런 사례가 하나뿐일 때
  - 사례 메모에 이미 넣은 영상(youtube 줄)은 그 사례로 본다.
  - 제목·설명에 금액(숫자+원/만 원/억, 시세·견적가·매입가)이나 결과 약속 표현이 있으면 넣지 않는다.
  - 둘 이상과 맞거나 하나도 안 맞으면 "짝 못 찾음". RSS 에서 빠져도 `data/shorts_matches.json` 에 남아 매일 다시 맞춰 본다(사례가 나중에 생기면 그때 붙음).
  - 사람이 고칠 때: 그 영상 항목에 `"case": "<사례 slug>", "manual": true`.
- 넣는 곳
  - 사례 페이지: "영상으로 보기" 칸(메모의 영상 + 짝 맞춘 쇼츠).
  - 동·구·시·안내 페이지: 사례 카드 묶음 바로 아래, 보이는 사례 중 짝 맞춘 쇼츠가 있는 첫 사례의 영상 1개(`shorts.cards_video_html`).
- 모양: 썸네일(i.ytimg.com, loading="lazy")과 재생 단추만 두고, 누르면 그때 youtube-nocookie 영상 창을 만든다(lite embed). autoplay 를 넣지 않아 저절로 재생되지 않는다. 쇼츠는 9:16(폭 320px까지), 긴 영상은 16:9.
- 구조화 데이터: 영상 칸마다 VideoObject(name, description, thumbnailUrl, uploadDate=RSS 올린 날, embedUrl, contentUrl). name 은 영상 제목이 아니라 "○○구 ○○동 ○○ 사례 영상", description 은 사례 요약.
- 영상 제목은 페이지 글자에 쓰지 않는다(제목에 "수출 안 됩니다" 같은 단정이나 금액이 있을 수 있어 콘텐츠 원칙과 부딪힘).
- 검사: `check_pages.check_video_embeds` 가 미리 넣은 iframe, 자동재생, 사례 페이지 밖에서 영상 칸 2개 이상, 필수 칸 빠진 VideoObject 를 오류로 막는다.
- 날짜: 영상 칸이 새로 들어간 페이지만 내용이 바뀌므로 그 페이지만 "최종 업데이트"·dateModified·sitemap lastmod 가 바뀐다(기존 `with_updated_date` 방식).
- 보고: 3시 보고에 오늘 짝 맞춘 쇼츠와 "짝 못 찾음" 목록.

## [5] 쇼츠 설명란 링크·촬영 공식

- 병한님이 말한 "쇼츠 배포.md"라는 파일은 없다. 설명란·고정 댓글·링크 규칙은 `병한-업무위키\마케팅\유튜브쇼츠\촬영편집틀.md` ⑦-6에 있고, "쇼츠 영상 제작" 세션은 그 폴더 CLAUDE.md 를 따라 이 파일을 먼저 읽는다. 그래서 이 파일을 고쳤다.
- ⑦ 링크: 첫 화면 `https://pyecha119.com/?src=yt` 대신 그 차 지역의 **동 페이지 → 없으면 구 페이지** 주소(`?src=yt`, 인코딩). 둘 다 없을 때만 첫 화면.
  - 주소 찾기: `python scripts/region_url.py "목포시 용해동"` (이 저장소). 법정동 목록으로 지역을 정하고 regions.json·gu.json 을 보고 인코딩된 주소를 출력한다.
  - 쇼츠 설명란·고정 댓글은 2026-10-11 규칙(쇼츠에서는 링크가 안 눌려 `pyecha119.com` 글자만)을 그대로 두고, 지역 페이지 주소는 롱폼 설명란과 당근·스레드 등에 쓴다.
  - 쇼츠와 사례의 짝 맞추기가 잘 되게, 사연 줄에 동 이름이나 "○○○○년식"을 넣는다([4]).
- 촬영 공식(⑥): 말하면서 찍는 영상의 **맨 끝 5초**에 카메라 보고 "지역(동까지)·차종·연식·사정" 한 줄. 손님 이름·번지·차 번호는 말하지 않는다. 쇼츠·롱폼 편집 때 이 5초는 잘라내고, 사례 사진도 이 5초에서는 뽑지 않는다([2]). 영상은 `폐차_인박스` 에 올린다([1]).
