# 행정구역 개편 반영 + 틀린 페이지 수정 계획 (2026-09-29)

이 파일은 계획서입니다. 실제 작업은 새 세션에서 **맨 아래 코드 상자 하나**의 지시문을 그대로 따라 합니다. 코드 상자 밖의 글은 설명입니다.

## 배경

- `data/fact_checks/existing-check-2026-09-29.json`·`.md` 에 기존 360개 페이지의 사실 확인 결과가 있습니다. 틀림(`bad`) 21개, 근거 못 찾음(`unverifiable`) 11개, 옆 동에 있음 24개, 장소 이름 아님 12개입니다.
- 2026년 7월 1일부터 행정구역이 바뀌었습니다(사실 확인됨).
  1. 인천 중구·동구 → 제물포구·영종구로 통합·조정, 인천 서구 → 서구·검단구로 분리
  2. 광주광역시 + 전라남도 → 전남광주통합특별시 출범

## 영향받는 기존 페이지: 38개 (전체 360개 중)

## 1. 새 이름과 옛 이름을 함께 보여주는 방법

- **새 이름이 기준, 옛 이름은 "(옛 ○○)"로 한 번씩.** 예: 제목 "인천 제물포구 신포동 폐차 비교매입", 첫 문장과 meta description 에 "(옛 중구 신포동)". 검색엔진이 가장 많이 보는 제목·첫 문단·설명문에 두 이름이 다 있어 옛 이름 검색에도 계속 잡힙니다. 제목에 옛 이름까지 넣으면 길어져 오히려 손해라 본문·설명문에만 넣습니다.
- 첫 화면 아래 회색 한 줄: "2026년 7월 1일부터 인천 중구 원도심은 제물포구가 되었습니다. 옛 주소로 문의하셔도 됩니다."
- 데이터로 처리: `regions.json` 에 `old_sido`·`old_sigungu`·`old_code`·`renamed_on` 칸을 더하고, 템플릿은 그 값이 있을 때만 "(옛 …)"과 안내 줄을 넣습니다. 페이지 38개를 손으로 고치지 않습니다.
- `check_pages.py` 의 "다른 시도 이름이 본문에 있음" 검사가 `old_*` 값은 오류로 잡지 않게 합니다.

## 2. 페이지 주소(URL)는 그대로

- 이미 검색엔진에 등록된 주소이고, 사이트맵·사례 페이지·인근 지역 링크가 모두 이 주소를 가리킵니다. GitHub Pages 는 서버 리다이렉트가 안 돼 주소를 바꾸면 검색 점수를 처음부터 다시 쌓아야 합니다.
- 앞으로 새로 만드는 페이지만 새 이름으로 주소를 만듭니다(`jemulpo`, `yeongjong`, `geomdan`. 광주·전남은 기존 `gwangju-`, `jeonnam-` 접두어 유지).

## 3. 루틴이 쓰는 지역 목록 고치기

1. 행정안전부 법정동코드 최신본으로 `legal_dong_list.csv` 의 해당 623줄을 새 시도·시군구·코드로 교체(옛 줄은 지움).
2. `regions.json` 38개 항목의 `sido`·`sigungu`·`code` 를 새 값으로 바꾸고 옛 값은 `old_*` 에 남김. `pick_next_regions.py` 는 코드와 (시도, 시군구, 동) 이름 둘 다로 중복을 거르므로 둘을 같이 바꿔야 같은 동을 또 뽑지 않습니다.
3. 스크립트 4곳 사전에 "전남광주통합특별시"(짧은 이름·slug 접두어·정렬 순서)를 넣습니다. 통합시 안에서 옛 광주 자치구를 어떻게 적는지는 새 세션에서 공식 자료로 확인해 정합니다.
4. CLAUDE.md 의 "다른 시도의 지역 이름을 쓰지 않습니다" 규칙에 옛 이름 예외를 한 줄 적습니다.

4. 코드 작업 (검색 없음): CSV → 스크립트 사전 → 템플릿 → `regions.json`(38개 이름 + 21개 글) → 전체 렌더링 → `check_pages.py` 통과
