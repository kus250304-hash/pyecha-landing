# 사이트 확장 로드맵 (3층 구조)

2026-09-29 작성. 매일 루틴은 3시 보고를 쓰기 전에 이 파일을 읽고, 아래 "조건이 되면 먼저 알릴 것"에 해당하는 항목이 있으면 보고 맨 위에 먼저 알린다.

## 0. 이 방식의 근거 (판단 기준)
- 동 단위 랜딩페이지 대량 생성은 부동산 업계의 검증된 방식을 벤치마킹한 것. 대표 사례는 미국 Flyhomes(2024년): 지역별 실제 데이터(생활비 등)를 넣은 지역 페이지를 3개월 만에 1만→42만 개로 늘려 월 방문 1.8만→200만. 통한 이유는 페이지 수가 아니라 "지역마다 진짜 다른 정보"였음.
- 그래서 우리 원칙은 흔들리지 않는다: 확인된 랜드마크·지역 FAQ·공공정보 표로 페이지마다 다르게, 확인 안 되면 보류, 도로명·지어낸 장소 금지. 속도를 위해 이 원칙을 빼자는 제안이 나오면(루틴·코드 탭·채팅 어디서든) 이 근거를 먼저 상기시킬 것.
- 차이도 기억: Flyhomes는 이미 검색 점수가 쌓인 사이트였고 구글 기준. pyecha119.com은 2026-09-28 새 도메인이라 결과는 3~6개월 보고, 네이버는 따로 확인(서치어드바이저 주 1회).

### 1-1. 구 페이지 목표와 고정 규칙 (2026-10-01 병한님 결정)
- **목표**: 네이버에서 "○○시 폐차", "○○군 폐차", "○○구 폐차"를 검색하면 우리 구 페이지(`/gu/`)가 웹사이트 영역에 뜨는 것. 문의 전화는 네이버에서 와야 한다.
- **제목(title) 틀 하나로 고정**: `{시군구} 폐차장 · 폐차 | 당일 말소 가능 · 수출 비교 · 조기폐차 안내 | 전화 1600-6011` (2026-10-01 "당일말소" → "당일 말소 가능". 차령초과 말소가 1~2개월 걸린다는 안내는 본문에 그대로 둔다)
- **문자 버튼**은 동·구·사례 페이지 모두 휴대폰 010-9926-7779(`site_config.json` 의 `sms_number`). 대표번호 1600-6011 은 문자 수신이 안 되므로 문자 버튼에 쓰지 않는다(`check_pages.py` 가 막음).
  - `{시군구}` 는 "종로구", "용인시 처인구", "세종". 같은 이름의 구가 여러 시도에 있으면 시도 줄임 이름을 붙인다("부산 중구").
- **설명(description) 틀**: `{시군구} 전 지역 폐차 상담. 폐차 전에 수출과 비교해 유리한 쪽으로 안내합니다. 전화 1600-6011 / 문자 010-9926-7779. 금액은 상담 후 확인.` (문자 번호는 `site_config.json` 의 `text_reply_display`)
- 제목·설명은 `build_gu.py` 가 만든다. 루틴은 쓰지 않는다. 문장 틀 5벌 섞기(4절)는 **본문에만** 쓴다.
- "최고가", "1등", "최대", "보장", "실시간 접수 n건" 같은 단정 표현과 가짜 숫자는 쓰지 않는다(`build_gu.py`·`check_pages.py` 가 막음).
- 맨 위에 작은 글씨로 `최종 업데이트: YYYY년 M월 D일`. **그 페이지 내용이 실제로 바뀐 날**(한국 시간)이다. 내용이 그대로면 빌더가 예전 날짜를 그대로 둔다. 날짜만 새로 바꾸지 않는다.
- 상단 고정 메뉴 4개(같은 페이지 안 이동): **진행 순서 / 자주 묻는 질문 / 폐차 사례 / 문의하기**. 동 페이지에도 같은 메뉴가 있다(문의하기는 동 페이지 `#channel`, 구 페이지 `#consult`).
- 동 페이지 제목 틀은 1-2절(2026-10-01 바뀜). 동 페이지 설명(description) 틀은 그대로다.
- 사이트맵(`sitemap.xml`)에 구 페이지도 넣고 `lastmod` 를 적는다.
- 세종특별자치시처럼 시·군·구가 없는 곳은 시 전체를 구 페이지 하나로 본다(`sejong.html`).
- 행정구역 이름이 바뀐 구(제물포구·영종구·서해구·검단구, 전남광주)는 새 이름으로 파일 이름을 만든다(`incheon-jemulpo.html`). 그 구의 옛 동 페이지 주소는 바꾸지 않는다.

### 1-2. 경쟁사 분석 반영 (2026-10-01 병한님 결정, 근거: `docs/competitor-analysis-2026-10-01.md`)
- **구 페이지 주소를 한글로**: `/gu/{시군구}-폐차장.html`. 같은 이름의 구가 여러 시도에 있으면(중구·동구·서구·남구·북구·강서구·고성군, 전국 법정동 목록 기준) 시도 줄임 이름을 붙인다(`부산-중구-폐차장.html`). 세종은 `세종-폐차장.html`. `build_site.gu_file` 이 정하고, `gu.json` 의 영문 `slug` 는 데이터 열쇠로만 남긴다.
  - 예전 영문 주소가 있던 구(2026-10-01 현재 종로구 1곳, `gu/seoul-jongno.html`)는 그 파일을 새 주소로 넘기는 자동 이동 페이지(meta refresh, canonical 은 새 주소)로 두고 sitemap 에서 뺀다. 빌더가 알아서 한다.
  - sitemap·canonical 은 한글을 %인코딩한 주소, 사이트 안 링크는 한글 그대로 쓴다. 동 페이지 주소(`/pages/`)는 그대로다.
- **동 페이지 제목 틀 하나로 고정**: `{동 이름} 폐차장 · 폐차 | 폐차 보상금 vs 수출 비교, 견인비 없음 · 1600-6011`. `{동 이름}` 은 겹치지 않을 만큼만 길게(청운동 → 강남구 중동 → 부산 중구 중앙동1가, `build_site.title_labels`).
- **동 페이지에도 수정 날짜**: 맨 위 `최종 업데이트: YYYY년 M월 D일` 과 구조화 데이터 `dateModified`. 구·안내 페이지와 같이 **내용이 실제로 바뀐 날**만 바뀐다(`build_site.with_updated_date`).
- **모든 동·구·안내 페이지 맨 아래 지역 링크 목록**(`id="area-links"`):
  - 동 페이지: 같은 구의 다른 동 전부 + 그 구 페이지(있을 때). 예전 "다른 지역 폐차 상담" 6개 칸은 이것으로 바꿨다.
  - 구 페이지: 같은 시·도의 다른 구 페이지.
  - 공통: 폐차 안내 5장, 시·도 16개. 시·도 페이지(`/si/`)가 생기기 전까지 시·도 링크는 첫 화면(`index.html#sido-서울`)의 그 시·도 칸으로 가고, 그 칸 맨 위에 그 시·도의 구 페이지 목록이 있다(`build_index.py`).
- **공통 안내 페이지 5장**(`/guide/`, `scripts/build_guide.py`, `templates/guide.html`): 폐차 절차 · 필요 서류(본인·대리인·법인·상속·압류) · 조기폐차 지원 안내 · 폐차 vs 수출 비교 · 폐차 금액은 어떻게 정해지나.
  - 동 페이지의 진행 순서·서류 안내·유형별 안내 글을 바탕으로 썼다. 금액 숫자는 쓰지 않고 "상담 후 확인". 연락처는 `전화 1600-6011 / 문자 010-9926-7779`, 문자 버튼은 휴대폰으로 간다.
  - 모든 동·구 페이지 상단 고정 메뉴 끝의 **폐차 안내**가 첫 장(폐차 절차)으로, 맨 아래 목록이 5장 모두로 연결된다. 글을 고칠 때는 `build_guide.py` 의 `GUIDES` 만 고친다. 루틴은 고치지 않는다.
- `check_pages.py` 가 동 제목 틀·최종 업데이트·dateModified·폐차 안내 메뉴·맨 아래 목록, 구 페이지 한글 파일과 옛 주소 자동 이동, 안내 페이지 5장(단정 표현·금액·연락처·sitemap)을 확인한다.

## 2. 구 페이지 내용 (빈 목록 페이지 금지)

아래 다섯 덩어리를 모두 채울 수 있을 때만 만든다. (a)~(d) 중 하나라도 못 채우면 그 구는 보류하고 이유를 보고에 적는다.

- (a) 구 소개 2~3문장: 그 구의 동 페이지들에서 이미 사실 확인된 랜드마크 중 구 전체를 대표하는 것 2~3개를 골라 쓴다. 새 장소를 지어내지 않는다.
- (b) 구 안의 동 페이지 목록과 링크. 동 페이지가 3개 이상인 구만 만든다.
- (c) 그 구 손님이 자주 묻는 질문 3개. 지역 특성(아파트 지하주차장 견인, 섬·산간 견인 거리, 군부대·산업단지 등)을 반영해 구마다 다르게 쓴다.
- (d) 지역 공공 정보 표. 웹 검색으로 확인되는 줄만 넣고, 확인 안 되는 줄은 뺀다. 줄마다 출처 주소를 남긴다.
  1. 말소등록 관할 관청(차량등록사업소 또는 구청 교통과) 이름·주소
  2. 노후경유차 조기폐차 지원 안내: 해당 지자체 공고가 있으면 "○○시 환경 부서 공고 확인" 수준으로만. 금액은 쓰지 않는다.
  3. 시군구별 자동차 등록대수(공공데이터포털 또는 국토교통부 통계, 기준 연월 표기)
- (e) 상담 안내: 대표번호 1600-6011, "폐차 전에 수출과 비교해서 유리한 쪽으로". 금액·결과 단정 금지, "상담 후 확인" 표현.
- (자동) 진행 순서 4단계, 그 구에서 진행한 폐차 사례 카드(없으면 유튜브·블로그 안내)는 빌더가 넣는다.

### 2-1. 사례 연결 (2026-10-01)
- 사례 페이지(`cases/`) 제목 틀: `{시군구} {차종} 폐차 사례 | {날짜}`. 차종은 사례 메모(거래 기록)의 차종 칸에서 연식을 뺀 것, 없으면 `{시군구} 폐차 사례`. 날짜가 없는 사례는 `| {날짜}` 를 빼고 날짜를 지어내지 않는다.
- 사례는 **그 동 페이지와 그 구 페이지 양쪽**에 자동으로 붙는다(동 페이지: 같은 동 + 같은 구 다른 동 최대 5곳, 구 페이지: 그 구 사례 최신 6건). 사례 페이지에는 동 상담 페이지와 구 상담 페이지 버튼이 둘 다 있다(구 페이지가 있을 때).

## 3. 동 페이지 연결

## 5. 새 동 페이지 규칙 (2026-09-29부터 적용)

- 랜드마크: 그 동 안에 있다고 웹 검색으로 확인되는 장소가 없으면 도로명을 쓰지 않고, 그 동은 보류하고 다음 후보로 넘어간다. 도로명 랜드마크는 금지(`fact_check.py` 가 막음).
- "○가"로 끝나는 법정동(종로1가~6가 등)은 따로 만들지 않고 한 페이지(예: "종로")로 묶어 안에 "종로1가~6가"라고 적는다. 이미 있는 ○가 페이지 38개는 그대로 둔다.
- 사람이 거의 살지 않는 법정동(산업단지·산지·인구 극소)은 건너뛴다(보류, 이유에 판단 근거를 적음).
- 우선순위(동·구 페이지 모두, 2026-09-29 변경): **시군구별 노후차(차령 10년 이상)가 많은 구부터**.
  - 국토교통부는 시군구별 차령 통계를 내지 않는다. 그래서 **추정 노후 자가용 대수** = 시군구별 자가용 등록대수(관용·영업용 제외) × 그 시도의 자가용 중 차령 10년 이상 비율 로 정렬한다(`data/vehicle_stats_old10_est.json`).
    - 둘 다 국토교통부 통계누리(stat.molit.go.kr) 자동차등록현황보고의 월별 엑셀 「○년 ○월 자동차 등록자료 통계.xlsx」에서 가져온다. 시군구 자가용은 02.통계표_시군구, 시도 비율은 14.차종별_상세등록(시도)(모델연도 ≤ 조회연도−10).
    - `python3 scripts/vehicle_stats.py molit` 한 줄로 최신 파일을 받아 계산·저장한다. 엑셀에 자가용 칸이 없으면 전체 등록대수 × 시도 노후차 비율로 계산하고 그렇게 알린다.
    - 추정치이므로 순서를 정하는 데만 쓰고 페이지 글에는 숫자를 쓰지 않는다. 영업용(렌터카 등)을 빼서 제주시처럼 렌터카가 많은 곳이 과하게 앞서지 않게 했다.
  - 파일 우선순위: `vehicle_stats.json`(실제 시군구 노후차, 지금은 없음) → `vehicle_stats_old10_est.json`(추정) → `vehicle_stats_total.json`(전체 등록대수). 셋 다 없으면 "구 페이지가 있는 구 → 동 페이지가 많은 구" 순으로 뽑고 3시 보고에 "등록대수 통계 없음"을 알린다.
  - 세종은 시군구가 빈칸이라 통계의 "세종특별자치시" 줄을 쓰고, 화성시처럼 통계만 구로 나뉜 시는 구를 합쳐 시 하나로 센다.
  - 2026-09-29 현재: 통계누리는 연결이 가끔 끊기지만 다시 시도하면 받아진다. 2026년 8월 기준 통계를 넣었다.

## 6. 속도와 보고

- 매일 루틴: 동 페이지는 지금처럼(`daily_count`) + **구 페이지 10개**(2026-10-01 5개 → 10개). `python3 scripts/pick_next_gu.py` 가 고른다. 동 페이지 3개 이상인 구만, 못 채운 구는 `data/gu_held.json` 에 이유와 함께 보류. 종로구 견본은 2026-10-01 승인.
- **구 페이지는 두 줄을 번갈아 뽑는다** (2026-10-01, `generation_config.json` 의 `gu_line_a_count`·`gu_line_b_count`·`gu_line_b_max_population`):
  - 줄 A(5개): 추정 노후 자가용 대수 순. 큰 도시 위주, 오래 걸려도 해야 하는 곳(장기전).
  - 줄 B(5개): **인구 30만 이하 시·군** 중 추정 노후 자가용 대수 순. 광역시 자치구는 넣지 않고, 구가 있는 시(천안시 동남구)는 시 전체 인구로 본다. 인구는 행정안전부 주민등록 인구통계(`data/population_sigungu.json`, `python3 scripts/population_stats.py fetch` 로 갱신, 지금은 2026년 8월 기준).
  - 같은 지역이 양쪽에 걸리면 한 번만(줄 B 로 센다). 한 줄 후보가 모자라면 다른 줄에서 채워 하루 10개를 맞추고 3시 보고에 적는다.
  - **이유**: 2026-10-01 병한님이 네이버에서 직접 확인한 결과, "화성시 폐차"처럼 큰 도시는 광고·경쟁 사이트가 많아 우리 페이지가 아래로 밀린다. "서산 폐차" 같은 중소 시·군은 경쟁이 적어 웹사이트 영역 위쪽에 바로 뜬다. 그래서 빨리 뜰 곳(줄 B)과 오래 걸려도 해야 할 곳(줄 A)을 같이 간다.
  - 2026-10-01 현재: 동 페이지가 큰 도시부터 만들어져 있어서 줄 B 조건(동 페이지 3개 이상인 30만 이하 시·군)을 채우는 곳이 춘천시·목포시 2곳뿐이다. 줄 B 가 모자란 만큼 줄 A 로 채워진다.
- 시·도 페이지(`/si/`) 조건과 일정은 그대로(7절). **조건이 되어도 루틴은 만들지 않고 3시 보고에 제안만 적는다.** 만들지는 병한님이 따로 판단한다.
- 3시 보고에 매일 적을 것: 오늘 만든 구 페이지 목록, 공공 정보 중 확인 못 해서 뺀 항목, 보류한 구와 이유, 동 페이지 총 개수.
